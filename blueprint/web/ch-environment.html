1 Lean 4 Environment Setup

Agentic Hallucinations — Independent Study. Target OS: Windows.

This document walks through installing Lean 4, connecting it to Mathlib, and verifying a working end-to-end setup. It also explains the pieces (elan, lake, lean-toolchain) you’ll be switching between constantly once the agent\(\leftrightarrow \)Lean harness is running.

1 What you’re installing

Three components, each with a distinct job:

Component

Role

elan

Version manager. Installs and switches Lean toolchain versions automatically per-project (reads lean-toolchain). Analogous to nvm for Node or pyenv for Python.

lake

Lean’s build tool and package manager (bundled with elan). Creates projects, resolves dependencies, builds, and runs executables. Analogous to cargo or npm.

Lean 4 VS Code extension

Editor integration. Talks to the Lean language server, renders the goal state (Infoview), shows diagnostics inline.

You do not install “Lean” directly — elan installs and manages the actual lean compiler versions on demand, per project.

2 Prerequisites

Open Command Prompt and confirm Git and curl are present: 

git --version
curl --version

If either errors, install Git for Windows (accept defaults; choose VS Code as Git’s default editor when prompted) and reopen the terminal.

Install VS Code if you don’t have it. In the installer, check “Add to PATH” and “Register Code as an editor for supported file types.”

3 Install elan

Open a new terminal (PowerShell or Command Prompt) and run: 

curl -O --location https://elan.lean-lang.org/elan-init.ps1
powershell -ExecutionPolicy Bypass -f elan-init.ps1

When prompted, choose 1 for the default installation. Then clean up and restart your terminal: 

del elan-init.ps1
exit

Open a fresh terminal and confirm: 

elan --version
lake --version

Both should print version numbers. If lake is not recognized, close and reopen the terminal (elan modifies your PATH, which only takes effect in new shells) — or restart your machine if that doesn’t resolve it.

4 Install the Lean 4 VS Code extension

In VS Code: Ctrl+Shift+X \(\rightarrow \) search lean4 \(\rightarrow \) install the official extension published by leanprover. Choose “Trust Publisher & Install” if prompted. This opens the Lean 4 Setup Guide, which double-checks the above steps automatically — worth glancing at, but everything in it is covered here.

Sanity check:

  1. Ctrl+N \(\rightarrow \) new file \(\rightarrow \) Ctrl+S \(\rightarrow \) save as Test.lean anywhere.

  2. VS Code will silently download a full Lean toolchain in the background (a progress popup appears bottom-right; the Infoview is unavailable until this finishes — can take several minutes the first time).

  3. Type #eval 1 + 1 into the file.

  4. Hover over eval — you should see a tooltip showing 2, with no red squiggles.

If that works, Lean itself is installed correctly.

5 Create a project

Everything in Lean lives inside a project — a folder with a lakefile.toml/lakefile.lean (dependency + build config) and a lean-toolchain file (pins the Lean version). A loose .lean file outside a project will throw confusing errors, especially once you import anything.

Two project types you’ll use:

A. Plain project (no Mathlib) — for isolated tactic experiments: 

lake new MyLeanProject
cd MyLeanProject
lake build

B. Mathlib-dependent project — for anything touching real math (topology, algebra, set theory — i.e. your actual problem set): 

lake +leanprover-community/mathlib4:lean-toolchain new MyMathlibProject math
cd MyMathlibProject
lake build

The math keyword adds Mathlib as a dependency so import Mathlib works. First build after this can take a while — it’s fetching Mathlib’s dependency graph.

5.1 Working in an already-cloned repository

Everything above (lake new ... math) is for starting a project from scratch. Joining a project that already exists — this one, for instance — is a different situation: the repository already carries its own lakefile.toml and lean-toolchain, so you skip lake new/lake init entirely and simply clone it. 

git clone https://github.com/drmithileshkumar/agentic.git
cd agentic

What to refresh. A fresh clone has no .lake/ directory — it’s gitignored, and entirely regenerable, so it is never part of what you clone. Refreshing it means fetching the prebuilt Mathlib cache and building: 

lake exe cache get
lake build

Note that lake update is not needed here. That command resolves dependencies to newer versions — a different operation, covered below in “Keeping things updated.” A first clone should build against exactly what lake-manifest.json already pins.

A lake gotcha worth knowing. lake init <package-name> <template> takes the package name first and the template second (std/exe/lib/math). If the folder is literally named math, running lake init on its own parses math as the package name with no template given — and you silently get a plain std project rather than the Mathlib-enabled one you wanted. Keep the project folder’s name distinct from math, and always pass the template explicitly: 

lake init myproject math

Fetch the prebuilt Mathlib cache (do this — avoids compiling Mathlib from source, which takes hours): 

lake exe cache get

Open the project in VS Code: code . from inside the folder, or File > Open Folder. Click “Trust authors” when prompted.

6 Verify Mathlib is wired up

Create MyMathlibProject/MyMathlibProject/Test.lean: 

import Mathlib.Topology.Basic

#check TopologicalSpace

With the cursor on the last line, the Infoview (right-hand panel; restore with Ctrl+Shift+Enter if it’s hidden) should show: 

TopologicalSpace.{u} (α : Type u) : Type u

No errors \(\rightarrow \) the environment is fully wired: elan \(\rightarrow \) lake \(\rightarrow \) Mathlib \(\rightarrow \) VS Code language server \(\rightarrow \) Infoview.

7 Leanblueprint set up

Leanblueprint turns a LaTeX blueprint into a website with a dependency graph, plus a PDF.

7.1 Installing it

This repository already has this done — the virtual environment and leanblueprint were added at commit d2ed81a — so the instructions below are for reference, or for reproducing the setup elsewhere, rather than something you need to redo in this checkout.

Install it into a project-local virtual environment rather than globally: 

python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install leanblueprint

Add .venv/ to .gitignore — it’s a local environment, not project content.

7.2 Two dependencies for a full local build

Beyond the Python package, a full local build needs two pieces of system software:

  • Graphviz — renders the dependency graph, via the dot and tred binaries.

  • A TeX distribution (MiKTeX or TeX Live) — needed for the PDF, and also for kpsewhich, which the HTML path uses to locate files. So this is required even if you only ever build the website.

Neither is installed by pip. CI already has both, so pushing and letting the workflow build is a reliable fallback if you’d rather not install them locally.

7.3 How blueprint/src is organized

content.tex assembles the blueprint by \input-ing each chapter in order. web.tex and print.tex are the two entry points — the website and the PDF respectively — and both pull in the same content.tex. Individual chapters live in blueprint/src/chapters/.

7.4 Build commands

Run these from the blueprint/ directory: 

leanblueprint web          # build the website
leanblueprint pdf          # build the PDF
leanblueprint serve        # serve the website locally
leanblueprint checkdecls   # check declarations named in the blueprint exist in Lean

8 Project anatomy (what’s actually on disk)

MyMathlibProject/
├── lakefile.toml          # dependencies, build targets
├── lean-toolchain         # pins exact Lean version (elan reads this)
├── lake-manifest.json      # resolved dependency versions (like a lockfile)
├── .lake/                  # build artifacts, downloaded deps — safe to delete/regenerate
└── MyMathlibProject/
    └── Test.lean           # your actual Lean source

lean-toolchain is the important one for environment switching: elan silently swaps the active Lean version based on whatever this file says, per-project, with no manual intervention. If two projects pin different Lean versions, moving between their folders in a terminal changes which lean/lake binary actually runs — this matters once the agent harness is juggling multiple project directories.

9 Command line vs. VS Code — two ways to talk to Lean

You’ll use both, for different purposes:

  • VS Code (interactive): editing proofs by hand, reading goal states, learning tactics. This is where you work.

  • Terminal / lake env lean / lake build: batch-checking a file, scripting, and — critically — how the agent harness will talk to Lean. The agent won’t have an Infoview; it will invoke Lean non-interactively (or via the Lean REPL / language server protocol) and parse structured output. Understanding what VS Code is doing under the hood is understanding the harness.

Run a single file from the command line to see raw output (no pretty Infoview): 

lake env lean MyMathlibProject/Test.lean

No output = success. Errors print as plain text — this is closer to what the agent will actually receive.

10 Keeping things updated

curl -L https://raw.githubusercontent.com/leanprover-community/mathlib4/master/lean-toolchain -o lean-toolchain
lake update
lake exe cache get
lake build

Run this inside a project when Mathlib has moved on and you want the latest version.

Note: this section is for pulling a newer Mathlib version into a project you’re already working in. If you’ve just cloned the repository for the first time, you don’t need lake update — see “Working in an already-cloned repository” above instead.

11 Troubleshooting

curl: (35) schannel: next InitializeSecurityContext failed during lake exe cache get — usually antivirus intercepting downloads. Disable it temporarily and re-run with the force flag: 

lake exe cache get!

uncaught exception: no such file or directory (error code: 2) — a corrupted toolchain download. Fix:

  1. Delete the offending folder under C:\Users\<you>\.elan\toolchains

  2. Delete the matching file under C:\Users\<you>\.elan\update-hashes

  3. Re-run lake build — it re-downloads automatically.

Disk cleanup — safe to delete: .lake/ inside any project (regenerates on build), old entries in ~/.elan/toolchains, and ~/.cache/mathlib.
