3 Lean 4 Tactic Cheat Sheet

Agentic Hallucinations — Independent Study — Quick Reference (4 pp.).

Sources: lean4.dev/tactics, Theorem Proving in Lean 4, Mathlib tactic docs. Full bibliography: docs/resources.md.

1 Reading a goal state

case succ
n : Nat
ih : n + 0 = n
⊢ n + 1 + 0 = n + 1

Everything above ⊢ is the context (hypotheses/variables in scope). What’s after ⊢ is the goal — what you still need to prove. Multiple goals are numbered/separated; · (a centered dot) focuses on the first one.

Term mode vs. tactic mode: theorem foo : P := proof_term is term mode (you write the proof object directly). theorem foo : P := by tac1; tac2 enters tactic mode — each tactic transforms the goal state until none remain. This project works almost entirely in tactic mode, since that’s what the agent proposes one step at a time.

2 Core / structural — closing and opening goals

Tactic

Does

Example

intro x

Introduces a hypothesis/variable from → or ∀

intro n hn

intro ⟨a, b⟩

Introduces + destructures (∧, ∃) in one step

intro ⟨hp, hq⟩

intros

Introduces everything possible, auto-named (avoid in final proofs — unreadable names)

intros

exact e

Closes the goal with an exact proof term e

exact Nat.add_comm a b

exact?

Searches the library for a term that closes the goal

exact?

apply e

Unifies e’s conclusion with the goal; leaves premises as new goals

apply Eq.trans

apply?

Searches the library for a lemma to apply

apply?

assumption

Closes the goal if some hypothesis matches exactly

assumption

rfl

Closes goals true by computation/definitional equality

rfl

have h : T := proof

States + proves an intermediate fact h : T

have hq : Q := hpq hp

have h : T := by tac

Same, proved with tactics

have : a ≤ a + b := by omega

let x := val

Local transparent definition (unfolds automatically)

let m := n + n

suffices h : T by tac

Replaces goal with T, using tac to show T → original goal

suffices h : n ≤ n+n by omega

show T

Restates the goal as a definitionally-equal T (for clarity)

show x > 10

constructor

Applies the goal type’s constructor (splits ∧, builds structures)

constructor

use e / exists e

Provides a witness for ∃

use 5

have vs let: have produces an opaque proof (only its type matters downstream); let produces a transparent value (its definition is visible to rfl/unification). Use have for propositions, let for reusable computed values.

3 Rewriting & simplification

Tactic

Does

Example

rw [h]

Replaces LHS of h : a = b with RHS, first match only per pass, all matches per rewrite pass

rw [Nat.add_zero]

rw [← h]

Rewrites right-to-left

rw [← h]

rw [h1, h2]

Chains rewrites left to right

rw [h1, h2]

rw [h] at h2

Rewrites inside hypothesis h2 instead of the goal

rw [h1] at h2

nth_rewrite 1 [h]

Rewrites only the n-th matching occurrence

nth_rewrite 1 [Nat.add_comm]

simp

Repeatedly applies the @[simp] lemma database until fixed point; often closes the goal outright

simp

simp [h1, h2]

simp + extra lemmas/hypotheses

simp [Nat.add_comm]

simp only [l1, l2]

Uses only the listed lemmas — reproducible, preferred in libraries

simp only [Nat.add_zero]

simp_all

Simplifies goal and every hypothesis, using hypotheses as rewrite rules too

simp_all

simp?

Runs simp, suggests the minimal simp only [...] that achieves the same

simp?

simp at h

Simplifies a hypothesis instead of the goal

simp at h

dsimp

Definitional-only simplification (unfolds, no lemma rewriting; never fails oddly)

dsimp [myDef]

norm_num

Proves/simplifies goals with concrete numerals

norm_num

norm_cast / push_cast

Normalizes / pushes numeric-type coercions (ℕ→ℤ→ℚ, etc.)

norm_cast

unfold f

Unfolds a definition f by name

unfold triple

rw vs simp: rw = precise, one rule at a time, you name every step. simp = automatic, applies many rules, less predictable. Reach for rw when you know the exact steps; simp when the goal is “obviously” simplifiable and you don’t care about the trace.

4 Case analysis, induction, destructuring

Tactic

Does

Example

cases x with | c1 => ... | c2 => ...

Splits on constructors of x’s type

cases n with | zero => rfl | succ m => omega

induction x with | c1 => ... | c2 ih => ...

Proof by induction; each non-base case gets an induction hypothesis ih

induction n with | zero => rfl | succ m ih => simp [ih]

rcases h with ⟨pat⟩

Recursive destructuring of ∧, ∃, nested pairs (Mathlib)

rcases h with ⟨n, hn⟩

obtain ⟨pat⟩ := h

Same as rcases, “goal-first” phrasing; also works to introduce a fresh existence proof

obtain ⟨n, hn⟩ := h

rintro (pat)

intro + rcases pattern in one step

rintro ⟨a, b⟩ ⟨c, d⟩

left / right

Picks a disjunct of an ∨ goal

left

match x with | pat => ...

Pattern-match in tactic mode (alternative to cases)

match n with | 0 => rfl | n+1 => omega

rcases pattern syntax: ⟨p1, p2⟩ destructs pairs/∃/∧ · p1 | p2 splits ∨ · rfl substitutes an equality immediately · _ discards · - clears the hypothesis after use.

5 Automation / decision procedures

Tactic

Solves

Notes

ring

Polynomial identities over (semi)rings — + - * ^ by constants, no division/inequalities

requires import Mathlib.Tactic.Ring

ring_nf

Normalizes a ring expression without requiring it close the goal

good mid-proof simplification step

field_simp

Clears denominators in field expressions (run before ring if division present)

field_simp; ring

omega

Linear arithmetic over ℕ/ℤ: + - < ≤ = ≠, mult/div/mod by constants

fails on variable×variable (non-linear)

linarith

Linear (in)equalities from hypotheses, ordered fields

linarith [extra_fact] to feed in a fact

nlinarith

linarith + limited nonlinear preprocessing (products, squares)

nlinarith [sq_nonneg x]

polyrith

Finds polynomial proofs via Gröbner bases (calls an external service)

slower; last resort over ring/nlinarith

decide

Evaluates a Decidable proposition to true/false

can be slow/blow up — see native_decide

native_decide

Like decide, compiled native code — much faster, less trusted

use for large finite checks

tauto

Closes propositional-logic tautologies

tauto

aesop

General automated proof search over registered @[aesop] rules

aesop, or aesop? to see the found proof

Decision table: polynomial equality \(\rightarrow \) ring. Division present \(\rightarrow \) field_simp then ring. Linear Nat/Int \(\rightarrow \) omega. Linear inequalities generally \(\rightarrow \) linarith. Nonlinear inequalities \(\rightarrow \) nlinarith. Concrete numerals \(\rightarrow \) norm_num. Definitional/computed equality \(\rightarrow \) rfl.

Example

  _ < c := h2

8 Combinators (gluing tactics together)

Combinator

Does

t1 <;> t2

Runs t2 on every goal produced by t1

· tac

Focuses the first goal, closes it with tac or fails

first | t1 | t2

Tries t1; if it fails, tries t2

repeat tac

Repeats tac until it fails

all_goals tac

Runs tac on every goal; fails if tac fails on any

any_goals tac

Like all_goals try tac, but fails only if tac succeeds nowhere

(tac1; tac2)

Sequences tactics without requiring the goal close by the end (unlike ·)

11 Common gotchas

  • rw fails silently-ish if the LHS pattern isn’t syntactically present in the goal — check with #check on the lemma first.

  • simp can over-simplify and leave a goal in an unexpected shape mid-proof; prefer simp only in anything meant to be stable.

  • omega/ring are decision procedures for specific fragments — omega fails on any variable×variable term; ring fails on inequalities or division. Route to the right tool (see the automation table above).

  • Nat subtraction truncates at 0 (a - b = 0 when a < b) — omega knows this, manual reasoning often doesn’t.

  • have is opaque, let is transparent — swapping them can silently break a proof that relied on unfolding.

  • sorry/admit compile successfully — always grep a file for sorry before treating it as done. (This is exactly the kind of silent failure the agent-hallucination logging in this project needs to catch — see docs/resources.md §5–6.)
